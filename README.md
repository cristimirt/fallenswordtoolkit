# Fallen Sword Toolkit

A userscript for [Fallen Sword](https://fallensword.com/) that improves the backpack, the Guild Store and other pages. Free and open source (MIT).

**Install:** open **https://cristimirt.github.io/fallenswordtoolkit/** and click Install (you need the [Tampermonkey](https://www.tampermonkey.net/) browser extension). What you install is a small loader; the toolkit itself is fetched from the site on every page load, so it updates by itself.

## What it does

- **Backpack:** search as you type, filters for level, set, rarity, craft, hell forge, guild tagged and more, item counts on the type icons, locked items, and a backpack pop-up from the top bar.
- **Break down:** a button next to world loot, and an optional automatic break down with a log.
- **Guild Store:** a list or tile window with search, filters and sorting. Take or deposit several items at once, and take or recall items from other members.
- **Reward pages:** on the Loyalty and PvP Ladder rewards pages, the details of every item next to it, search and type filters, and buying several at once.
- **Potion Bazaar:** the name and buffs of every potion under it, and buying several at once (the Helper's multi-buy is left to the Helper).
- **Composing:** when there is not enough gold to start or instantly finish a potion, one button withdraws what is missing from the bank and does it; or switch on Automatic Bank Withdrawal.
- **Arena Token Shop:** item names, search and type filters, and buying several at once.
- **Skills Guide:** every skill with its type, who can learn it, the potions that give it and a bonus calculator.
- **Markets:** a searchable Buff Market, and search boxes and colour filters in the Auction House.
- **World map:** a wiki button, Footprints kept after a reload, a Path Finder (with a switch for portals), and a search box over the portal's list of destinations; on world maps, tooltips that sit under each place and show the zone's level.
- **Quick Buff:** a draggable window with the buffs a target already has.
- **Also:** draggable sidebar widgets, and it works next to the Fallen Sword Helper.

Settings are in the **FST** tab of the game's Preferences page. To see a game page without the toolkit, add `toolkit=off` to its address.

## How it is built

The toolkit is ES modules under `src/`, bundled with esbuild into one file. A small userscript, the loader (`loader/fs_toolkit.user.js`), is all that is installed in Tampermonkey: on every page it reads `manifest.json` from the GitHub Pages site, imports the bundle it names and starts it.

| Path | What |
|---|---|
| `loader/fs_toolkit.user.js` | the loader (rarely changes; Tampermonkey updates it from the install page) |
| `src/main.js` | the entry point: starts every feature |
| `src/core/` | shared pieces: jQuery, dialogs, settings storage, requests to the game, tooltips, item data, item type buttons, search and multi-buy for the shops |
| `src/features/` | one module per feature: `backpack`, `actionlist` (break down button), `markets`, `bagpopup`, `sidebars`, `wiki`, `pathfinder` (+ `route`), `guildstore`, `loyalty`, `arenashop`, `bazaar`, `skillguide`, `notifications`, `quickbuff`, `autobreak`, `settingsui` (quick settings and the FST tab) |
| `tools/build.mjs` | builds `dist/`: the bundle, `manifest.json`, the loader and the install page |
| `tools/serve.mjs` | the development server (see below) |
| `.github/workflows/` | `deploy.yml` publishes `dist/` to GitHub Pages on every push to `main`; `check.yml` builds on pull requests |

`src/features/route.js` is generated by `tools/sync-helper.js` of the Fallen Sword Path Finder project (`node tools/sync-helper.js <path>/src/features/route.js`): edit the routing there, not in this copy.

## Developing and testing

```
npm install
npm run dev
```

(or run `dev-server.bat`). This builds the dev bundle, serves it on `http://127.0.0.1:8787/` (`PORT=1234 npm run dev` for another port) and builds again whenever a file in `src/` changes.

Tell the loader to use it, once, in the console of a game tab (`fallensword.com`, not `www`):

```js
localStorage.setItem('FST_dev_base', '8787')   // a port, host:port or a whole address
```

Reload the game page after each change. `localStorage.removeItem('FST_dev_base')` goes back to the published toolkit. Run `npm run check` before pushing.

## Releasing

Work on the `Dev` branch, open a pull request to `main`. A push to `main` builds and publishes the site (the build number is the workflow run number; every page load of a player picks up the new build). Raise `version` in `package.json` for a new toolkit version. The loader only needs a new `@version` when the loader itself changes. One-time setup: in the repository on GitHub, Settings > Pages > Source: **GitHub Actions**.
